# BI чат-бот: дашборд по вопросу прямо в чате

Решение кейса Puzzle RPA «Чат-бот с интерактивной визуализацией данных» (SK Challenge 2026, Технопарк «Сколково»).

Менеджер пишет вопрос на русском: «Собери дашборд по продажам, план-факт по регионам и торговым точкам за последний год». Бот сам находит данные, показывает единую таблицу и строит дашборд прямо в переписке: KPI-карточки, фильтры с поиском, переключатели и четыре связанных графика. Дальше работа идет диалогом: «добавь процент выполнения плана», «перестрой третий график», «покажи только Центральный», «сохрани как Продажи Q3».

## Главная идея: бот не пишет код

Обычный путь — дать LLM писать SQL и Python и закрывать это песочницей. Здесь код не генерируется вообще, поэтому выполнять нечего.

```
вопрос → команда из каталога → SQL собирает код → единая таблица → вычисления деревом формул → дашборд
```

1. **Каталог (семантический слой)** — `app/catalog.py`. Здесь один раз описано, что такое план, факт, скидка, регион, точка. Парсер и LLM выбирают только из каталога.
2. **Команда**. Фраза превращается в JSON: что показать, за какой период, по каким разрезам. Если периода нет, бот уточняет.
3. **SQL собирает код** — `app/db.py`. Только SELECT, имена колонок из каталога, значения фильтров параметрами, таймаут 15 секунд, лимит строк.
4. **Вычисления после выгрузки** — `app/compute.py`. «Факт минус план, делить на план, умножить на 100» становится деревом `{op, a, b}`. Дерево считается в pandas и в браузере одним алгоритмом. Допустимы только + − × ÷, числа и колонки таблицы.
5. **Дашборд — сохраненное состояние** — `app/store.py`. Запрос, таблица, вычисления, графики, фильтры, переключатели. Отсюда сохранение, список, поиск, копия, переименование, история версий и отмена шага.

Чтобы подключить базу клиента (в реальном проекте Oracle), меняется каталог, логика бота остается прежней.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000
# открыть http://localhost:8000
```

База по умолчанию — встроенная DuckDB: CSV из `data/` загружаются при старте, после этого доступ к файлам и сети отключается. Для PostgreSQL задайте `DATABASE_URL` (роль только на чтение), загрузка данных — `scripts/load_postgres.sql`. Бот проверен на DuckDB; для PostgreSQL используется та же сборка SQL, на живой базе ее стоит проверить отдельно.

### Бесплатная LLM (необязательно)

Бот работает и без LLM: запросы разбирают правила каталога. LLM подключается для формулировок, которые правила не узнали.

| Вариант | Настройка |
|---|---|
| Ollama на своем компьютере, бесплатно, данные не уходят наружу | `ollama pull qwen2.5:7b`, переменные не нужны |
| Groq, бесплатный тариф | `LLM_BASE_URL=https://api.groq.com/openai/v1 LLM_MODEL=llama-3.1-8b-instant LLM_API_KEY=...` |

`LLM_MODE=fallback` (по умолчанию) — сначала правила, потом LLM; `primary` — сначала LLM; `off` — только правила. Ответ модели проходит проверку по каталогу.

## Что умеет

- Дашборд по вопросу: 4 графика (план-факт по периодам, структура, ТОП по разрезу, динамика выполнения плана), KPI сверху с цветом, текстовое резюме.
- Простые вопросы дают 1–2 графика: план-факт по регионам, структура, сравнение с выделением отстающих, скидки клиента по причинам.
- Фильтры: выпадающие списки с поиском, мультивыбор, каскад «регион → точка». Применяются ко всем графикам и KPI.
- Переключатели: разрез, метрика (включая добавленные колонки), месяц / квартал / год, значения / % к плану / динамика.
- Вычисления диалогом: отклонение, процент выполнения, динамика к прошлому периоду и году, доля, накопительный итог, средний чек, ранг, произвольная формула словами. Статистика по группам: среднее, медиана, min, max.
- Правка графиков: «отсортируй третий график по проценту выполнения», «покажи четвертый график с учетом динамики», «ТОП-10».
- Дашборды: сохранить, сохранить как новый, список, поиск по названию и тексту запроса, открыть в том же виде, переименовать, удалить, копия, история версий, отмена последнего шага.
- Экспорт: HTML-файл дашборда (работает без интернета) и Excel с таблицей и вычислениями.
- Синхронный зум графиков по периодам, подсказки с точными значениями, переключение серий в легенде.

## Структура

```
app/catalog.py   семантический слой: разрезы, метрики, словари
app/db.py        доступ только на чтение, сборка SQL по спецификации
app/compute.py   вычисляемые колонки: дерево формул, доли, динамика, накопительный итог
app/nlu.py       разбор русского текста в команду
app/llm.py       бесплатная LLM через OpenAI-совместимый API, проверка ответа по каталогу
app/bot.py       диалог: команда → изменение состояния → сообщения
app/store.py     сохранение дашбордов и версий
app/main.py      FastAPI: чат, API, экспорт
static/          чат и дашборд (Plotly, без сборки фронтенда)
tests/           точность и безопасность
data/            тестовые данные кейса
```
